# device-inventory-management-portal-179092-179102

This workspace contains the inventario_database container (PostgreSQL) for the multi-container Inventory app.

Contents:
- inventario_database/startup.sh: Starts PostgreSQL, creates DB/user, grants permissions, and applies schema.sql idempotently.
- inventario_database/schema.sql: Defines the inventory_items table, indexes, and trigger to auto-update updated_at.
- inventario_database/db_connection.txt: Convenience psql connection string (generated by startup.sh).
- inventario_database/db_visualizer/postgres.env: Env file for the included simple DB viewer.

Database details:
- Default DB: myapp
- Default user: appuser
- Default password: dbuser123
- Default port: 5000

Connection:
- psql CLI:
  - psql -h localhost -U appuser -d myapp -p 5000
  - Or use the generated command in inventario_database/db_connection.txt
- URL: postgresql://appuser:dbuser123@localhost:5000/myapp

Environment variables (used by helper tools within this container):
- POSTGRES_URL, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB, POSTGRES_PORT
These are written to inventario_database/db_visualizer/postgres.env after startup.

Schema:
- Table: inventory_items
  - Columns: id SERIAL PK, asset_tag UNIQUE NOT NULL, type, brand, model, serial_number, status, assigned_to, location, purchase_date DATE, warranty_expiry DATE, notes, created_at TIMESTAMP DEFAULT now(), updated_at TIMESTAMP DEFAULT now()
  - Indexes: (type), (status), (assigned_to)
  - Trigger: updates updated_at on every UPDATE
- The schema is applied automatically by startup.sh in an idempotent way:
  - Uses CREATE TABLE IF NOT EXISTS, CREATE INDEX IF NOT EXISTS, and CREATE OR REPLACE FUNCTION.
  - A .schema_applied.marker file is created to avoid re-applying on subsequent runs.

Notes:
- This database container lists specific env variables (POSTGRES_URL, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB, POSTGRES_PORT). Frontend-specific variables like REACT_APP_* are not used here.
- If you modify schema.sql, delete inventario_database/.schema_applied.marker to force re-application on next startup, or run:
  - psql -h localhost -U appuser -d myapp -p 5000 -f inventario_database/schema.sql
